
# Redis数据类型与业务场景

# 一、基础五大核心数据类型（必背）
1. String 字符串
特点：最简单 KV，支持数字自增、过期、分布式锁；
适用场景：普通业务缓存、接口 token、计数器、库存控制、分布式锁；
常用命令：set/get/incr/ex。
2. Hash 哈希
特点：key 对应多个 field-value，可单独更新单个字段，无需序列化整对象；
适用场景：用户信息、购物车、商品结构化数据；
常用命令：hset/hget/hincrby/hdel。
3. List 有序可重复链表
特点：头尾读写 O (1)，中间遍历慢；可左 / 右进出；
适用场景：简易消息队列、评论列表、浏览记录、分页下拉；
常用命令：lpush/rpop/lrange。
4. Set 无序去重集合
特点：自动去重，支持交集 / 并集 / 差集运算；
适用场景：全局数据去重、好友 / 共同好友、商品标签；
常用命令：sadd/sismember/sinter/sunion/sdiff。
5. ZSet 有序去重集合
特点：元素绑定 score 分数自动排序，去重；
适用场景：排行榜、热度榜单、延时任务、限流滑动窗口；
常用命令：zadd/zrevrange/zrank。

## 二、三种特殊扩展类型（加分项）
Bitmap 位图：底层是 String，按 bit 存储；用户签到、日活统计，极致省内存；
HyperLogLog：概率基数统计，固定 12KB 内存估算 UV，允许微小误差；适合网站独立访客统计；
Streams：Redis 专业消息队列，支持消费组、消息 ack、持久，替代简易 List 队列。
三、面试标准口述话术
面试官您好，Redis 分为五大基础类型和三类特殊类型：
String：基础 KV，用作缓存、计数器、分布式锁；
Hash：存储结构化对象，可单独修改某个字段，适合用户、购物车；
List：有序链表，实现简易队列、评论、历史分页；
Set：自动去重，利用交并差计算共同好友、标签；
ZSet：带分数有序集合，做各类排行榜、延时任务；
扩展类型：Bitmap 做签到统计，HyperLogLog低成本统计UV，Streams 是可靠消息队列支持消费组。
业务开发根据数据结构特征选择对应类型，减少序列化开销，提升读写性能。
