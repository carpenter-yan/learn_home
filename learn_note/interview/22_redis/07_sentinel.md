
# Redis Sentinel 哨兵 面试精简笔记
一、哨兵四大核心功能
监控：持续 PING 检测 Master、Slave 与其他哨兵节点健康状态；
通知：节点故障、切换完成后推送告警给客户端 / 运维；
故障转移 Failover：主客观下线后自动选举新主，切换所有从节点复制目标；
配置中心：客户端连接哨兵获取当前有效 Master 地址。
二、哨兵集群部署规范
必须部署奇数个哨兵（推荐 3 个），避免半数投票分裂；
quorum：判定主客观下线所需最小哨兵票数（3 哨兵配置 2）；
majority：执行故障转移需要过半哨兵授权（3 哨兵 majority=2）；
2 哨兵缺陷：若一台机器整体宕机，仅剩 1 哨兵无法满足 majority，无法切换。
三、下线判定机制（SDOWN / ODOWN）
主观下线 SDOWN
单个哨兵 PING 超时，单方面判定节点故障，仅自身标记，不触发切换。
客观下线 ODOWN
达到 quorum 数量哨兵均判定主 SDOWN，集群统一认定主故障，开启故障转移。
四、哨兵集群自动发现
哨兵通过__sentinel__频道 Pub/Sub 互通：
每 2 秒广播自身监控信息；
自动感知同套主从的其他哨兵，同步监控配置。
五、Slave 升 Master 选举优先级（依次判断）
断开主时间过长，直接淘汰；
slave-priority 优先级数值越小越优先；
replica offset 同步偏移量越大（数据越完整）优先；
runId 最小者兜底。
六、故障转移完整流程
Master 标记 ODOWN；
哨兵集群选举一个 Leader 哨兵执行切换；
按规则选出最优 Slave 升级为新 Master；
所有 Slave 改为复制新 Master；
旧 Master 恢复后自动降级为 Slave；
哨兵同步新主配置给客户端、其他哨兵。
七、哨兵架构两大数据丢失问题与解决方案
1. 异步复制丢数据
   主写入成功，数据未同步到 Slave 就宕机，新主缺失这批数据。
2. 脑裂（网络分区双主）
   主与哨兵断连，哨兵选出新主；旧主仍接收客户端写入，网络恢复旧主清空同步新主，写入数据丢失。
   防护配置（双参数配合）
   plaintext
   min-slaves-to-write 1
   min-slaves-max-lag 10
   含义：主必须至少有 1 个从同步延迟≤10 秒，否则拒绝写入；脑裂 / 同步滞后最多丢失 10 秒数据。
   八、哨兵架构局限性
   只有单一 Master，无法水平扩容写并发；海量高写场景改用 Redis Cluster；
   主从异步复制，无法做到数据零丢失，只能降低丢失范围。
   九、面试口述标准话术
   面试官您好，哨兵是 Redis 主从配套高可用方案，核心四大能力：监控、告警、自动故障转移、提供主节点配置。
   部署建议 3 个哨兵奇数集群，依靠 SDOWN 主观、ODOWN 客观双层判定避免误切换，通过 Pub/Sub 自动发现对等哨兵；
   主故障后按优先级、同步 offset 选举最优从升新主，自动调整所有从节点复制目标；
   架构存在异步复制、脑裂两类数据丢失风险，通过 min-slaves 系列参数限制同步延迟，把丢失控制在 10 秒内；
   哨兵仅解决单点故障，不支持写扩容，大数据高并发场景选用 Redis Cluster 集群。
