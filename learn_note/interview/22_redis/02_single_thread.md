# Redis单线程模型

## 一、概念澄清（高频误区）
常说 Redis单线程，仅指处理客户端命令的主线程；持久化、异步删除、过期清理等任务由独立子进程/后台线程执行，并非整个进程只有一个线程。
Redis6.0 引入多线程 IO，但是命令执行依旧单线程串行，仅网络读写分发多线程优化。

## 二、核心底层：事件循环 + IO多路复用
两大事件处理器
文件事件：监听 Socket 连接、读写客户端请求，Linux 底层用 epoll；
时间事件：定时清理过期 key、AOF 重写、RDB 快照等后台任务。
IO多路复用工作流程
主线程把所有客户端Socket注册到epoll，无请求时阻塞休眠；有连接可读/可写时内核通知主线程，串行处理就绪连接，一个线程支撑上万并发连接。

## 三、单线程设计三大优势
- 无锁竞争，无需同步
所有命令串行执行，不存在多线程修改数据结构，不用加锁，无死锁、无锁竞争开销，代码简洁。
- 消除线程上下文切换开销
多线程频繁切换会损耗 CPU，单线程全程复用同一线程，高并发下性能更稳定。
- 内存操作极快
所有数据存内存，GET/SET 等命令执行耗时微乎其微，CPU 一般不是瓶颈，瓶颈在网络 IO。

## 四、单线程固有缺点
阻塞命令会拖垮整个服务
执行慢Lua脚本、keys全量遍历、大hash批量操作等耗时指令，会阻塞事件循环，所有客户端请求排队等待。
无法充分利用多核CPU，主线程只能跑单个核心。

## 五、生产规避阻塞方案
禁用keys *，改用 scan 渐进遍历；
精简 Lua 脚本，不做大规模循环计算；
拆分大集合，避免单 key 数据过大；
Redis6.0 开启多线程 IO 分担网络读写压力。

## 六、标准面试口述话术
Redis 所说单线程，特指处理客户端命令的主线程，持久化、过期清理由独立子进程处理。
底层依靠事件循环 + IO 多路复用 epoll，单线程监听海量 Socket 连接，无请求时休眠，高效处理并发；
单线程优势：串行执行不用加锁、无上下文切换开销，内存操作速度极快，轻松支撑高 QPS；
缺点：耗时命令会阻塞整个事件循环，且只能利用单核 CPU；生产环境禁止全量 keys、复杂 Lua 等阻塞操作，Redis6 可开启多线程 IO优化网络读写。
