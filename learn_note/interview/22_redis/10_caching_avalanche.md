
# 缓存雪崩、穿透、击穿

## 一、缓存雪崩 Cache Avalanche
1. 定义
   大量缓存 key 同时过期 / Redis 集群整体宕机，海量请求全部打到 MySQL，压垮数据库。
2. 解决方案（事前 + 事中 + 事后）
   事前预防
   过期时间加随机偏移，避免批量同时失效；
   Redis 主从 / 哨兵 / Cluster 高可用架构，防止整体宕机；
   RDB+AOF 持久化，故障可快速恢复数据。
   事中兜底
   应用本地二级缓存（Caffeine/Ehcache）；
   Hystrix/Sentinel 限流、降级，控制 DB 请求上限，返回默认兜底数据。
   事后恢复
   依靠持久化文件快速加载缓存，恢复流量。

## 二、缓存穿透 Cache Penetration
1. 定义
   查询数据库不存在的数据（如负数 ID、随机无效参数），缓存无记录，请求直达 DB，恶意攻击极易打垮库。
2. 解决方案
   缓存空值：DB 查无数据时，缓存一条短期空记录，拦截重复无效查询；
   布隆过滤器：前置过滤，将所有合法主键存入过滤器，不存在的 key 直接拦截，不查缓存与 DB；
   参数校验：接口层提前拦截非法 ID、异常参数。

## 三、缓存击穿（热点 key 失效）
1. 定义
   超高并发热点 key 刚好过期，一瞬间大量并发请求穿透缓存访问 DB。
2. 三种方案
   永不过期：静态热点数据不设置 TTL；
   分布式锁：过期时仅放行一个线程更新缓存，其余等待；
   主动续期 / 定时预热：后台定时提前刷新热点缓存，不让 key 过期。

## 四、面试口述标准话术
   缓存三大问题分开说明：
   缓存雪崩：大量 key 同时过期或 Redis 整体宕机，流量压垮数据库。事前打散过期时间、搭建 Redis 高可用；事中本地缓存 + 限流降级保护 DB；事后靠持久化快速恢复。
   缓存穿透：查询不存在数据绕过缓存直查 DB。常用方案缓存空值、前置布隆过滤器，同时接口做参数校验拦截非法请求。
   缓存击穿：热点 key 过期瞬间并发打库。静态热点永不过期；动态数据用分布式锁控制单线程更新，或定时主动预热缓存避免失效。
