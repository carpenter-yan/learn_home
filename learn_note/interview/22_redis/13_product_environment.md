# Redis 生产环境部署方案

## 一、面试考察重点
面试官考察线上实操经验：集群架构、机器配置、内存分配、容量规划、并发承载、高可用保障。

## 二、标准线上部署案例（Redis Cluster）
集群拓扑
共 10 台物理机，5 主 5 从；每台主机部署 1 个 Master，对应另一台机器部署 1 个 Slave，主从物理隔离。
机器硬件
8 核 CPU + 32G 内存 + 1T 磁盘。
内存分配规范
单 Redis 进程限制 10G 内存（不建议超过 10G，避免 fork 阻塞、持久化卡顿）；集群可用内存合计 50G。
容量数据
存储商品数据，单条约 10KB；常驻 200 万条，占用 20G 内存，仅使用集群总内存一半。
并发承载
单主峰值 5 万 QPS，集群理论上限 25 万 QPS；线上实际峰值约 3500 QPS。

## 三、高可用保障
每个主节点配备独立从节点；主宕机后集群自动故障转移，对应 Slave 升级为主，业务无感知。

## 四、核心生产规范
主从分机部署，避免单机故障同时丢失主、副本；
单实例内存控制 10G 以内，降低 RDB fork 阻塞风险；
预留一半以上内存余量，应对流量突增；
海量读写、大数据场景优先 Redis Cluster，天然分片 + 自动容灾。

## 五、面试口述话术
我们线上采用 Redis Cluster 5 主 5 从架构，10 台 8 核 32G 物理机，主从分开部署；每个 Redis 进程限制 10G 内存，防止 fork 阻塞。
集群总可用内存 50G，存储 200 万条商品数据仅占用 20G，预留充足余量；单主最高支撑 5 万 QPS，整体集群峰值 3500 左右。
架构自带高可用，主节点故障会自动将对应从提升为主，保障业务持续读写。
