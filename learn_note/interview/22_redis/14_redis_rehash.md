
# Redis 渐进式 rehash

## 一、底层基础
Redis 字典底层依靠两个哈希表 ht [0]、ht [1] 存储键值对；
rehashidx = -1：未进行 rehash；rehashidx >= 0：正在渐进迁移数据。

## 二、rehash 触发与新表容量规则
扩容：负载因子 > 5，新表容量取大于当前键数 ×2的最小 2 次幂；
缩容：负载因子 < 0.1，新表容量取大于当前键数的最小 2 次幂；
先给备用哈希表 ht [1] 分配对应内存空间。

## 三、核心：渐进式 rehash（分批迁移，不阻塞主线程）
执行逻辑
不一次性迁移全部数据，把迁移分摊到每一次读写操作；
每次执行增删改查时，顺带迁移rehashidx索引下所有节点，再将rehashidx自增；
所有节点迁移完成后，释放 ht [0]，把 ht [1] 改为 ht [0]，重置 rehashidx=-1。
设计优势
海量 key 场景下，不会一次性大量 IO / 计算阻塞 Redis 主线程，保证命令响应速度稳定。
过渡期间读写规则
查询：同时遍历 ht [0]、ht [1]；
新增：直接写入 ht [1]，避免 ht [0] 数据持续增长。

## 四、面试口述话术
面试官您好，Redis字典采用双哈希表结构，使用渐进式rehash避免大key阻塞：
扩容/缩容时先初始化备用哈希表 ht [1]，按 2 次幂分配容量；
不一次性迁移全部数据，每次读写顺带迁移一个索引下的所有节点，分摊计算压力；
迁移完成后切换哈希表、释放旧表；rehash 过程中查询需要遍历两张哈希表，新键直接写入新表；
核心目的：海量数据场景防止集中迁移阻塞主线程，保障 Redis 高吞吐。
