
# 缓存使用场景、作用与风险

## 一、为什么引入缓存（两大核心价值）
1. 提升查询性能
   复杂SQL、多表关联查询MySQL耗时可达数百ms；将结果存入内存缓存后，读取仅几ms，性能提升上百倍。
   适用：读多写少、短时间内数据不频繁变更的业务场景。
2. 支撑高并发
   MySQL单机QPS上限约 2000；内存 KV 缓存单机可承载数万 QPS，并发能力远高于数据库。
   大量读请求拦截在缓存，减轻 DB 压力，避免数据库被打垮。

## 二、缓存使用带来的四大典型问题
   缓存与数据库双写数据不一致：更新DB后缓存未同步/删除，缓存残留旧数据。
   缓存穿透：查询不存在的数据，绕过缓存直接大量打数据库。
   缓存击穿：热点key过期瞬间，并发请求全部落到 DB。
   缓存雪崩：大量key同时过期，流量全部压垮数据库。
   补充：缓存并发竞争，多线程同时读写同一 key 引发数据错乱。

## 三、标准面试口述话术
   项目引入缓存主要解决两大问题：
   高性能：复杂数据库查询耗时高，热点数据存入内存缓存，查询耗时从几百 ms 降到几 ms，大幅优化响应速度；
   高并发：数据库单机并发能力有限，缓存单机可承载数万QPS，拦截大部分读流量，保护数据库。
   但缓存使用不当会带来一系列线上故障：缓存穿透、击穿、雪崩，以及缓存和数据库双写不一致、并发竞争等问题，开发时需要配套方案解决。
