
# Redis 高并发与高可用 面试精简笔记（原文精简版）

## 一、面试考察核心
面试官主要考察两点：
单机并发上限不够如何扩容、分摊读写压力；
Redis 节点宕机如何自动切换，保障服务不中断。

## 二、提升高并发方案（两类架构）
1. 一主多从（读写分离，读扩容）
   架构：单 Master 负责写入，多个 Slave 承担查询请求；
   性能：单机写可达几万 QPS，多从节点叠加读能力，整体读 QPS 可达 10 万 +；
   局限：只有一个主节点，写入无法扩容，不适合海量数据、高写入场景。
2. Redis Cluster 分片集群（读写均可扩容）
   适用：既要高并发，又要存储海量数据；
   能力：多主多从分片，读写请求分散到多台主节点，整体读写并发可达几十万 QPS；
   优势：突破单机内存、CPU 瓶颈，支持线性扩容。

## 三、实现高可用方案（两层架构）
1. 基础：主从复制
   仅实现数据多副本热备，主节点宕机后无法自动切换，需要人工修改客户端配置，不能独立作为高可用方案。
2. 完整高可用：主从 + Sentinel 哨兵
   哨兵不存储业务数据，仅监控全部主从节点；
   主节点故障时，哨兵集群自动完成故障转移：选举最优从节点升级为新主，所有从节点、客户端自动切换指向新主；
   无需人工介入，节点宕机业务无感知，线上中小业务标准高可用方案。

## 四、面试标准口述话术
   Redis 高并发和高可用分开说明：
   高并发扩容
   读压力大采用一主多从读写分离，主负责写、多从分担查询，读 QPS 轻松 10 万 +；如果写入量大、数据量大，使用 Redis Cluster 分片集群，多主节点分散读写，整体并发提升至几十万 QPS。
   高可用保障
   单纯主从只能备份数据，主宕机无法自动切换；搭配哨兵 Sentinel 集群实现完整高可用，哨兵监控所有节点，主故障后自动选出新主，自动同步拓扑，无需人工干预，保障服务持续可用。
