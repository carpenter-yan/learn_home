

# ElasticSearch分布式架构

## 一 、底层基础
ES底层封装Lucene，天然分布式多节点集群，对外屏蔽分片、路由、故障转移细节。

## 二、核心概念与 MySQL 类比（版本差异重点标注）
层级：Index → Mapping → Document → Field
Index：等价 MySQL 数据库，存放一类业务数据（如订单索引）；
Type：7.x 版本彻底移除，6.x 单索引仅允许 1 个 type，旧版类比数据表；
Mapping：等同于表结构，定义字段类型、分词规则；
Document：单条 JSON 数据，等价 MySQL 一行记录；
Field：文档内字段，等价表列。

## 三、分片 Shard（分布式扩容核心）
索引会拆分为多个分片，每个分片是独立 Lucene 索引，分两类：
Primary Shard（主分片）
唯一负责写入、更新、删除；
创建索引时指定数量，创建后不可修改；
分散到不同节点实现水平扩容、并行查询。
Replica Shard（副本分片）
主分片完整备份，主从不在同一台机器；
作用：节点宕机自动故障转移、分担查询读流量；
副本数量可随时动态调整。

分片两大价值
扩容：数据分散多节点，突破单机存储上限；
提速：读写并行执行，提升集群吞吐。

## 四、Master 主节点（集群管理者）
集群节点自动选举Master，仅负责元数据管理，不处理业务读写；
核心工作：创建/删除索引、分片分配、故障分片升降级；
故障处理：
Master宕机：集群重新选举新 Master；
普通数据节点宕机：Master将该节点上副本提升为主分片；
故障节点恢复：Master同步缺失副本，该节点仅保留副本，不再当主分片。

## 五、标准面试口述答题话术
ES 是基于Lucene的分布式搜索引擎，核心架构分为三层：
基础概念：Index类比数据库，7.x已废弃Type，Mapping定义字段结构，Document为单条数据；
分片扩容机制：索引拆分为主分片分散多节点，实现水平扩容与并行查询；每个主分片配置副本，副本跨机器部署，既分担读压力，又实现容灾；主分片创建后数量固定，副本可随时调整；
Master集群管控：集群自动选举主节点，专门维护索引元数据、分片分配；任意节点宕机时，Master自动把对应副本提升为主分片，节点修复后仅同步副本，保证集群高可用。
